## OpenClaw 的 token 都花在哪：三笔账

OpenClaw 智能体运行耗 token 量，拆开看就是三笔账。

第一笔是每条请求的“底薪”。OpenClaw 每次运行都会重新组装系统提示：工具列表、技能元数据、自我更新说明、SOUL.md 和 IDENTITY.md 这些人设与记忆文件、时间信息、运行环境元数据，全部随请求注入。实测拆过一条“你是什么模型”的账单——系统提示约 3200 tokens，SOUL.md 约 1800，技能定义约 1500，长期记忆约 800，消息格式脚手架约 280，合计 9585。这是固定支出，你说什么、问什么都省不掉。

第二笔是会话滚雪球。OpenClaw 发新消息时，会把之前的全部对话连同自己的历史回复一起重发。5 轮编程对话测下来，总成本是第 1 轮的 13.3 倍——哪怕老消息已经吃到缓存折扣，第 3 轮生成的长代码到了第 4、5 轮就成了昂贵的“阅读材料”。一条 12 万 tokens 的长回复（让写长文档时很常见）会把下一条请求直接顶到 13 万 tokens。走 Slack 或 WhatsApp 聊天更夸张：有实测发现某个用了三个月的频道，每条请求都背着 111KB 历史记录，约合 28000 个旧消息 tokens，按 Sonnet 输入价光这部分就是每次 $0.08。

第三笔是后台流量。心跳默认约每 30 分钟一次，每次都带完整上下文去问“有活干吗”，一天就是 200 万–300 万 tokens；Sonnet 价格下 $1–3/天，换成 Opus 能到 $5/天，一个月 $150 用来确认“我还活着”。这之外还有会话标题生成、输入联想、工具结果的后处理，每一样都背着全套上下文。叠加下来，后台任务能把真实用量放大 3–5 倍——你以为这轮会话用了 10 万 tokens，控制台显示 40 万。

## 查账：先搞清楚自己烧了多少

查账不用装第三方工具，OpenClaw 自带命令。聊天里发 /status，能看到当前模型、上下文占用、上一次回复的输入/输出 tokens 和预估成本；/usage tokens 或 /usage full 会在每条回复后面挂用量尾注，/usage cost 从本地会话日志直接汇总成本。想看更细的构成，用 /context list 和 /context detail，每个注入文件、每项技能占多少都列得清清楚楚。命令行下还有 openclaw status --usage，看的是供应商配额窗口，不是单条成本。

两个容易踩的坑。一是登录方式：走 OAuth 认证时 /status 只显示 token 数、不显示金额，想看钱必须用 API key。二是 /status 的费用预估依赖你在模型配置里填的单价——没填价格就只显示 tokens。顺带一提，这个成本字段的计价单位是美元（每百万 tokens，分输入/输出/缓存读写四档），人民币价格记得换算后再填，否则金额会错位。

查账时顺便理解一下缓存机制，它直接决定账单形态。相同前缀反复出现时，缓存命中的部分按一折左右计价，所以固定不变的 8000 token 底薪实际没那么贵；但缓存有 TTL（有效期），过期后整段历史按原价重算，挂机过夜后第一条消息特别贵就是这个原因。Anthropic 的缓存读取比普通输入便宜、写入反而加价，各家规则不同，接模型前值得看一眼。

## 把账单打下来的五个开关

五个开关按性价比排序，第一个就能砍掉大头。

### 1. 先算单价，再分工

同一批 tokens，在不同模型上的账单差的是数量级。以一条 9600 tokens 的普通消息、只算输入原价（按 1 美元≈7 元粗算）：

| 模型 | 输入单价（每百万 tokens） | 这一条消息的固定开销 |
| --- | --- | --- |
| Claude Opus | $15 | 约 $0.14（约 ¥1） |
| gpt-5.1-codex | $1.25 | 约 $0.012（约 ¥0.09） |
| qwen-plus（阿里云百炼） | ¥0.8 | 约 ¥0.008 |
| qwen-turbo（阿里云百炼） | ¥0.3 | 约 ¥0.003 |

放到心跳上更直观：一天 300 万 tokens 的心跳流量，Opus 一个月 $150，qwen-turbo 按原价算也就十几块人民币。复杂任务确实需要强模型，要改的只是分工——心跳、标题生成、格式整理这些杂活没必要用贵模型。OpenClaw 支持给不同任务指定不同模型：有 24GB 显卡的话，可以按省钱指南的做法用 Ollama 挂个本地 Qwen MoE 专门接心跳（llama.cpp 现在能直接转译 Anthropic 格式调用，零胶水代码）；没有 GPU，百炼这类按量 API 就是替代方案。👉 [开通百炼，新用户可先领免费 token 额度](https://www.aliyun.com/product/bailian?userCode=5eqf8rny)

### 2. 心跳别一刀切，先看缓存 TTL

直接关心跳，挂机成本归零，但定时提醒、自动巡检也没了。折中做法是拉长间隔并配合缓存 TTL：模型缓存有效期 1 小时的话，把心跳间隔设成 55 分钟左右，每次心跳都能命中刚写好的缓存，避免过期后全量重算。多 agent 配置里还能用 cacheRetention 参数按 agent 调缓存策略，通知类的 agent 可以干脆不写缓存。心跳间隔在网关配置里改。

### 3. 给上下文瘦身

SOUL.md 是最值得动的文件，它每次请求都跟着走。有人把它从 1800 tokens 精简到 400，每条请求省 1400 tokens，20 轮会话加后台任务累计能省 8 万–14 万。几个默认值记一下：单个引导文件超 20000 字符会被截断，全部引导注入默认上限 150000 字符；技能只注入元数据、详细说明按需读取，所以每多装 10 个技能，基线大约多 1200 tokens——用不上的关掉，人设文件里的旧记忆定期清理。

### 4. 会话纪律

长期不重置的会话是滚雪球的土壤。定时任务（cron）建议走隔离模式，每次从干净上下文开始，实测一个月能省 37% 左右；聊天会话别一聊几个月，话题告一段落就开新的。压缩（compaction）和会话修剪功能开着，让老历史折算成摘要。

### 5. 抓网页和发图片，成本结构完全相反

实测里最反直觉的一组数：让 agent 写一个带完整测试的 TypeScript 缓存模块，$0.033；让它抓一篇维基百科做总结，$0.180。网页又乱又长，agent 换着姿势试了 6 次工具调用，最后一轮上下文里堆了 32 万 tokens 的原始 HTML。图片反而是便宜货，识别一张 59KB 的图只要 $0.011。对应到使用习惯：网页抓取交给便宜模型，或限制重试次数；OpenClaw 默认把图片压到 1200px 再上传，纯看图可以把 imageMaxDimensionPx 调低，做 OCR 或看截图细节再调高。

## 几个高频问题

**OpenClaw 本身要花钱吗？** 软件开源免费。花钱的是三样：模型 API、跑网关的服务器，以及你没优化的后台流量。

**OpenClaw 一天耗多少 token 算正常？** 差异极大，别看平均值。只算心跳，默认配置下一天 200 万–300 万 tokens 是常态；正常干活的使用里，几分钟消耗 100 万–300 万 tokens 的报告也不少见；2150 万那种极端案例是“长会话不重置 + 全技能开启 + 后台任务全开”叠加出来的。跑一天 /usage 看自己的数，比看任何人的经验都准。

**心跳直接关掉行不行？** 行，挂机成本直接归零，代价是失去定时提醒和自动检查。更稳的做法是前面说的组合：拉长间隔，加缓存保温。

**换便宜模型会不会变笨？** 看任务。心跳、标题、格式整理这类杂活，便宜模型完全够；写代码、长文推理这类主任务，保留强模型按需切换。分工本身就是收益最大的一步，模型档次倒还在其次。
